Getting started

A searchable popover for native selects. Platypicker keeps the <select> as the source of truth, so forms, validation and your existing code keep working.

Install the package, import it once, and load the stylesheet.

Then wrap any select in <platy-picker>. Pick with the mouse or the arrow keys, or type the first letters of an option.

Search

search adds a filter box that matches as you type. It looks at the option text, the data-subtext shown on the right of a row, and group labels. Matches are highlighted.

Multiple and badges

Add multiple size="1" to the select. The closed picker shows the selected options as badges on one line, as many as fit, then a count of the rest. The × on a badge removes it with the mouse; from the keyboard, open the picker and toggle the option.

placeholder shows while nothing is selected. A required select keeps its last badge, so it has no ×.

Select all / none

controls adds All and None beside the search box, to select all or none of the options. All acts on the options that match the current filter. A single select only gets None, and a required one hides that too. The labels can be changed per picker, as here.

Groups and dividers

The popover follows the select's own structure: <optgroup> labels become headers, <hr> becomes a divider, and an option after a group gets one of its own. Disabled options and groups stay visible but can't be picked, and title becomes a tooltip.

Long lists

Long lists are rendered a batch at a time, and the next batch follows as you scroll down. Searching still covers every option, and the arrow keys and type-ahead go past the rendered rows. batch-size sets how many rows a batch has (50 by default), and batch-size="0" renders everything at once.

Loading as you scroll

When the options come from a server, add them as they arrive. loading says more are on their way: the end of the list stays marked, and the picker fires loadmore whenever that end comes near, including when it opens on a short list. Fetch the next page then, and remove loading once there's nothing left. The event fires again each time the end comes near, so ignore it while a fetch is still running.

placeholders shows skeleton rows at the end while you wait (10, or as many as you give it). This one waits most of a second per page of 20 cars.

Live changes

The select stays the source of truth. Add, remove or relabel options with the usual DOM methods, and the picker follows, open or closed. Attributes are live too, and each has a matching property.

setValue() selects by value and updates the badges and the list without firing change, as when a script sets select.value. Picks by the user fire change on the select.

    Theming

    The stylesheet draws a neutral look meant to sit well in most pages, in light and dark. Change it with --platypicker-* variables, set on platy-picker or any ancestor. Move the controls to try a few; the CSS tab follows.

    The default colors switch between light and dark with the page's color-scheme, so a page with a dark theme should say so. Use light-dark() to give your own colors for both.

    Class plugs

    Every element Platypicker creates has a fixed pp-* class you can style. Each part also has a plug: extra classes added next to the fixed one, empty by default, for dressing the picker in a framework's own classes. Two state plugs, itemSelected and itemDisabled, are on a row while its option is selected or disabled.

    Plugs are global, and elements read them when they are created. The pickers already in the page are created the moment platypicker is imported, so fill the plugs in a module of their own that imports classes.js, and import it first. The picker below runs in a frame of its own, so its plugs don't reach the rest of this page.

    Skins

    A skin fits Platypicker into a framework. Import it before platypicker, and the pickers look like the rest of the framework's forms. There's nothing extra to link: the skin brings its own few rules.

    The Bootstrap skin gives the select Bootstrap's form-select class, so sizes like form-select-sm and validation classes like is-invalid work as on any select. The popover and the badges take their colors, radius and shadow from Bootstrap's variables, so they follow your theme and data-bs-theme="dark", even on part of a page. Your own --platypicker-* variables still win. It needs Bootstrap 5.3 or later.

    Order matters here: the skin fills the class plugs, which the pickers read when they are created, and they are created as soon as platypicker is imported. A skin imported too late says so in the console.

    Browser support

    Platypicker needs appearance: base-select, along with anchor positioning and CSS nesting.

    • Chrome and Edge 135 and later.
    • Firefox 149 has it behind preferences that are off by default (customizable_select and appearance-base-select in about:config).

    Without support, <platy-picker> does nothing: the select inside it looks and works exactly as a plain one would, so forms keep working everywhere.

    A few things to keep in mind:

    • Only a direct child select is enhanced: <platy-picker><select>.
    • <platy-picker> is display: contents, so size and place the select as you would without it. A multiple select gets a minimum width of 14rem for its badges.
    • Avoid :has() selectors of your own that depend on the options, such as select:has(option:checked). Browsers re-check them for every option that changes, which turns Select all on a long list into seconds of work, in Firefox especially.
