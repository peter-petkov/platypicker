Getting started

A searchable popover for native selects. Platypicker keeps the <select> as the source of truth, so forms, validation and your existing code keep working.

Install the package, import it once, and load the stylesheet.

Without a build step, load the minified files in dist/ with plain tags, from a CDN for example: one script with every translation, 21 kB gzipped, and the stylesheet. platypicker.bootstrap.min.js and platypicker.tailwind.min.js are the same script with a skin applied first. The script sets window.PlatyPicker.

Then wrap any select in <platy-picker>. Pick with the mouse or the keyboard, or type the first letters of an option.

Search

search adds a filter box that matches as you type. It looks at the option text, the data-subtext shown on the right of a row, and group labels. Matches are highlighted.

The letters you type match in order, the first at the start of a word and the rest anywhere after it, so initials find an option: try "rdj" for Rio de Janeiro, or "tky", which finds Tokyo and, by its subtext, Istanbul in Turkey. Text inside a word matches too, as "bul" does in Istanbul. Case and accents don't matter.

Strong matches come first, those where every matched part starts a word, then the rest, each in list order. Type "s": New York, Cape Town, Sydney and Seoul come first, by a word starting with S in the city or its country, then Paris, Istanbul and Buenos Aires. An option group moves as a whole, with its best match. Rows only ever join below the ones shown, so nothing moves while you're about to pick it. While loading is set, and in lists of more than 50,000 options, matches stay in list order.

Multiple and badges

Add multiple size="1" to the select. The closed picker shows the selected options as badges on one line, as many as fit, then a count of the rest. The × on a badge removes it with the mouse; from the keyboard, open the picker and toggle the option.

placeholder shows while nothing is selected. A required select keeps its last badge, so it has no ×.

Select all / none

controls adds All and None beside the search box, to select all or none of the options. All acts on the options that match the current filter. A single select only gets None, and a required one hides that too. Their labels, like every text, come from the picker's language.

Groups and dividers

The popover follows the select's own structure: <optgroup> labels become headers, <hr> becomes a divider, and an option after a group gets one of its own. Disabled options and groups stay visible but can't be picked, and title becomes a tooltip.

Long lists

Long lists start with a batch of rows, and more are shown a few at a time as you scroll, so the scrollbar shrinks smoothly instead of jumping. Searching still covers every option, and the arrow keys, End and type-ahead go past the rows shown so far. batch-size sets how many rows the list works with at a time (50 by default): the rows shown first, and how far ahead it searches. batch-size="0" renders everything at once.

counter adds a line at the bottom of the popover with how many rows are shown out of all the options. It counts up as you scroll, so it shows how far the end is. With a search, it says how many options match: try "honda" here.

Loading as you scroll

When the options come from a server, add them as they arrive. loading says more are on their way: the end of the list stays marked, and the picker fires loadmore to ask for more before the list runs out, as soon as fewer than a batch are left to show. Fetch about event.detail.batchSize options then, and remove loading once there's nothing left.

The event also fires whenever the end of the list comes into view, which can be while a fetch is still running, so ignore it then. While loading, search, select all, End and type-ahead only know the options loaded so far, and matches stay in list order rather than putting the strong ones first. The README has the details, including searching on the server.

placeholders shows skeleton rows at the end while you wait (10, or as many as you give it), and counter says how many options have loaded so far. This one waits most of a second per page.

Live changes

The select stays the source of truth. Add, remove or relabel options with the usual DOM methods, and the picker follows, open or closed. Attributes are live too, and each has a matching property.

setValue() selects by value and updates the badges and the list without firing change, as when a script sets select.value. Picks by the user fire change on the select.

    Class plugs

    Every element Platypicker creates has a fixed pp-* class you can style. Each part also has a plug: extra classes added next to the fixed one, empty by default, for dressing the picker in a framework's own classes. Two state plugs, itemSelected and itemDisabled, are on a row while its option is selected or disabled.

    Plugs are global, and elements read them when they are created. The pickers already in the page are created the moment platypicker is imported, so fill the plugs in a module of their own that imports classes.js, and import it first.     Skins

    A skin fits Platypicker into a CSS framework by dressing it in the framework's own classes, so the pickers look like the rest of its forms. Switch the skin at the top of the page to see every example on it in that framework.

    Import the skin before platypicker: it fills the class plugs, which the pickers read when they are created, and they are created as soon as platypicker is imported. A skin imported too late says so in the console. There's no extra stylesheet to link.

    Platypicker's own look has two halves. Layout, how the parts sit, stays. Paint, the colors, borders, spacing and type, steps aside for a skinned picker and leaves it to the framework's classes, whichever stylesheet loads first. The skin adds a few rules of its own for what the framework has no class for, like the check mark and search matches. Your own --platypicker-* variables still apply to those.

    On phones

    On a phone the picker opens as a sheet along the bottom of the screen, with the same search, controls and list, laid out for touch. This one is a sheet everywhere, so you can try it here: layout="sheet".

    • It opens at a little over half the screen. Drag its handle or heading up or down, or pull the list down from the top; let go, it springs to half or full height, carrying on from the speed of the drag, or closes if it's low enough, with a light tick on Android. On a phone on its side it opens at full height, narrower and centred.
    • The select's label names it, with how many options are selected underneath. None and All sit either side.
    • Opening leaves the search box alone, so the keyboard stays down. Tap the search box and the sheet grows to full height above the keyboard, with Cancel beside it. Picking keeps the keyboard up; scrolling the list or Cancel puts it away, and the sheet goes back to its height.
    • A tap on the dimmed page only closes the sheet, so nothing under it reacts. On Android, Back closes it too.
    • It moves: the rows rise into place as it opens, a picked row dips as its check mark wipes in, the selected count rolls to its new number, and a search glides the rows that stay to their new places. With prefers-reduced-motion, none of it plays.

    layout="auto", the default, opens a sheet where PlatyPicker.sheetMedia matches, a touch screen the size of a phone either way up, checked each time a picker opens. layout="popover" never opens one. The sheet's look has variables of its own.

    layout="native" leaves the select to the browser instead, on every device: its own picker opens, without search, controls or subtext, and a multiple select shows no badges. It shows only the options in the select, so loadmore never fires there: load them all up front.

    Localization

    Each picker speaks the language of its nearest lang attribute. Platypicker's translation of that language loads the first time a picker needs it, so an English page loads none. Search ignores case and accents the way the language does: try "kase" in the German picker.

    It ships translations for 22 languages: Arabic, Bengali, Bulgarian, Chinese (simplified and traditional), French, German, Hindi, Indonesian, Italian, Japanese, Korean, Marathi, Polish, Portuguese, Russian, Spanish, Tamil, Telugu, Turkish, Urdu and Vietnamese. A regional tag uses its language (de-AT is German), and any other language stays English. Not every translation has been checked by a native speaker yet, and corrections are welcome.

    The translations are plain objects in src/languages/, one file per language. Import one to bundle it, or register texts of your own in PlatyPicker.languages, which win over Platypicker's text by text. A text with a count gives plural forms, picked by the language's own rules.

    Right to left

    In a right-to-left page or element (dir="rtl") the picker mirrors: the popover lines up with the select's right edge, and the chevron, badges and check marks swap sides.

    Browser support

    Platypicker needs anchor positioning (with anchor-scope) and the popover attribute. It uses appearance: base-select where the browser has it, and works without it.

    • Chrome and Edge 135 and later.
    • Firefox, current releases (tested in 160), with no flags.
    • Safari hasn't been tested yet.

    Without support, <platy-picker> does nothing: the select inside it looks and works exactly as a plain one would, so forms keep working everywhere.

    A few things to keep in mind:

    • Only a direct child select is enhanced: <platy-picker><select>.
    • <platy-picker> is display: contents, so size and place the select as you would without it. A multiple select gets a minimum width of 14rem for its badges.
    • Avoid :has() selectors of your own that depend on the options, such as select:has(option:checked). Browsers re-check them for every option that changes, which turns Select all on a long list into seconds of work, in Firefox especially.
    • Android's Back closes the sheet where there's a CloseWatcher, in Chrome and Edge. Firefox can't keep a closing popover on screen to slide away yet, so the sheet slides down first and then closes.
    • In Firefox, which has no appearance: base-select, a multiple select is a list box underneath: its options aren't laid out, which keeps a long list fast, so screen readers hear them only in the popover. A letter, Home, End or a page key on it selects one option in place, as in Chrome. The README has the details.

      What's new

      The highlights of each feature release. The changelog has the full list.

      2.1

      Platypicker 2.1 finds options by their initials, and puts the sheet on phones in motion.

      Search by initials

      The letters you type in the search box match in order, the first at the start of a word and the rest anywhere after it, the way an IDE finds a method by its initials: "nyc" finds New York City, "rdj" Rio de Janeiro and "lt" Laptop, with each matched part highlighted and the starts of words preferred. A word starts after a space or punctuation, at an upper case letter after a lower case one, and where letters and digits meet. Text inside a word still matches, as "rich" does in Zürich, so every search that found an option before still finds it. Strong matches, where every matched part starts a word, come first, then the rest, each in list order, so the best match is the first row.

      Motion in the sheet

      As the sheet opens, the rows in view rise into place one after another. It springs between half and full height, carrying on from the speed of a drag. A picked row dips slightly as its check mark wipes in, and the digits of "N selected" roll to the new count like an odometer. As a search filters the list, the rows that stay glide to their new places while the others fade in or out. All of it is left out with prefers-reduced-motion.

      Also in this release

      • Steady results: the rows of a search never reorder as more matches are found or loading ends, only when the search changes. While loading is set, and in lists of more than 50,000 options, matches stay in list order.
      • Highlights: every search match is highlighted, not only the first 100 on the page. PlatyPicker.maxHighlights is gone, and setting it does nothing.

      2.0

      Platypicker 2.0 drops the Bootstrap dependency in favour of a look of its own, and adds framework skins, batched rendering for long lists, a bottom sheet on phones, and localization.

      Built-in look and theming

      The stylesheet now draws a neutral look of its own, in light and dark, following the page's color-scheme. Colors, radii and shadows are --platypicker-* custom properties, and the rules have the specificity of a single class, so your own classes on the <select> take precedence.

      Framework skins

      Skins fit the picker into a CSS framework. The Bootstrap skin dresses it in Bootstrap's own classes, so sizes, validation and data-bs-theme work as on any form, and the Tailwind skin paints the base look with Tailwind 4's theme variables. Import a skin before platypicker, or add classes of your own to each part through class plugs.

      Badges for multiple selects

      A closed <select multiple size="1"> shows its selected options as badges on one line, then a +N count of those that don't fit. Each badge has a × to remove it, and placeholder sets the text shown while nothing is selected. The select stays underneath, so focus, keys and screen readers work on it as before.

      Batching

      Long lists render batch-size rows at a time (50 by default) and grow as you scroll, while search, select all and type-ahead still cover every option. With loading and the loadmore event, options can come from a server a page at a time, and counter shows how far through the list you are.

      Mobile support

      With the default layout="auto", pickers open as a bottom sheet on phone-sized touch screens. The sheet drags between half and full height, makes room for the on-screen keyboard while searching, and closes with Back on Android. layout="native" leaves opening to the browser's own picker instead.

      Localization

      Pickers take their texts from the nearest lang attribute, with 22 translations loaded on demand. PlatyPicker.languages overrides any text per language, plural forms follow Intl.PluralRules, search ignores case and accents, and dir="rtl" mirrors the layout.

      Also in this release

      • Accessibility: dialog and listbox semantics, the list as a single Tab stop, Home, End and Page keys, and support for forced colors.
      • Firefox: works without flags. Where appearance: base-select is missing, the picker opens its own popover from an ordinary select.
      • Shadow roots: pickers work inside them.
      • Live changes: edits to the options update only the rows they affect, so focus and scroll position survive.

      Coming from 1.x? Bootstrap's classes inside the picker became pp-* ones, and the text attributes gave way to the picker's language. Upgrading from 1.x lists every change.

      Earlier versions

      1.1

      Platypicker became the <platy-picker> element, wrapped around a select rather than switched on by data-toggle, with reactive search and controls attributes, skeleton rows, keyboard navigation, setValue() and :state(open). It still drew its popover with Bootstrap 5.

      1.0

      The first releases on npm: a class that turned a <select data-toggle="platypicker"> into a Bootstrap 5 dropdown, with search, select all / none, option groups, subtexts and type-ahead.

      About

      Platypicker is an open-source web component that enhances native selects, with no dependencies. It's developed on GitHub and published to npm. Bug reports and feature requests go to GitHub issues, and pull requests are welcome, including corrections to the translations.
