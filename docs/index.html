Getting started

A searchable popover for native selects. Platypicker keeps the <select> as the source of truth, so forms, validation and your existing code keep working.

Install the package, import it once, and load the stylesheet.

Then wrap any select in <platy-picker>. Pick with the mouse or the keyboard, or type the first letters of an option.

Search

search adds a filter box that matches as you type. It looks at the option text, the data-subtext shown on the right of a row, and group labels. Matches are highlighted.

Multiple and badges

Add multiple size="1" to the select. The closed picker shows the selected options as badges on one line, as many as fit, then a count of the rest. The × on a badge removes it with the mouse; from the keyboard, open the picker and toggle the option.

placeholder shows while nothing is selected. A required select keeps its last badge, so it has no ×.

Select all / none

controls adds All and None beside the search box, to select all or none of the options. All acts on the options that match the current filter. A single select only gets None, and a required one hides that too. Their labels, like every text, come from the picker's language.

Groups and dividers

The popover follows the select's own structure: <optgroup> labels become headers, <hr> becomes a divider, and an option after a group gets one of its own. Disabled options and groups stay visible but can't be picked, and title becomes a tooltip.

Long lists

Long lists start with a batch of rows, and more are shown a few at a time as you scroll, so the scrollbar shrinks smoothly instead of jumping. Searching still covers every option, and the arrow keys, End and type-ahead go past the rows shown so far. batch-size sets how many rows the list works with at a time (50 by default): the rows shown first, and how far ahead it searches. batch-size="0" renders everything at once.

Loading as you scroll

When the options come from a server, add them as they arrive. loading says more are on their way: the end of the list stays marked, and the picker fires loadmore to ask for more before the list runs out, as soon as fewer than a batch are left to show. Fetch about event.detail.batchSize options then, and remove loading once there's nothing left.

The event also fires whenever the end of the list comes into view, which can be while a fetch is still running, so ignore it then. While loading, search, select all, End and type-ahead only know the options loaded so far. The README has the details, including searching on the server.

placeholders shows skeleton rows at the end while you wait (10, or as many as you give it). This one waits most of a second per page.

Live changes

The select stays the source of truth. Add, remove or relabel options with the usual DOM methods, and the picker follows, open or closed. Attributes are live too, and each has a matching property.

setValue() selects by value and updates the badges and the list without firing change, as when a script sets select.value. Picks by the user fire change on the select.

    Class plugs

    Every element Platypicker creates has a fixed pp-* class you can style. Each part also has a plug: extra classes added next to the fixed one, empty by default, for dressing the picker in a framework's own classes. Two state plugs, itemSelected and itemDisabled, are on a row while its option is selected or disabled.

    Plugs are global, and elements read them when they are created. The pickers already in the page are created the moment platypicker is imported, so fill the plugs in a module of their own that imports classes.js, and import it first. The picker below runs in a frame of its own, so its plugs don't reach the rest of this page.

    Skins

    A skin fits Platypicker into a CSS framework by dressing it in the framework's own classes, so the pickers look like the rest of its forms. Switch the skin at the top of the page to see every example on it in that framework.

    Import the skin before platypicker: it fills the class plugs, which the pickers read when they are created, and they are created as soon as platypicker is imported. A skin imported too late says so in the console. There's no extra stylesheet to link.

    Platypicker's own look has two halves. Layout, how the parts sit, stays. Paint, the colors, borders, spacing and type, steps aside for a skinned picker and leaves it to the framework's classes, whichever stylesheet loads first. The skin adds a few rules of its own for what the framework has no class for, like the check mark and search matches. Your own --platypicker-* variables still apply to those.

    Localization

    Each picker speaks the language of its nearest lang attribute. Platypicker's translation of that language loads the first time a picker needs it, so an English page loads none. Search ignores case and accents the way the language does: try "kase" in the German picker.

    It ships translations for 22 languages: Arabic, Bengali, Bulgarian, Chinese (simplified and traditional), French, German, Hindi, Indonesian, Italian, Japanese, Korean, Marathi, Polish, Portuguese, Russian, Spanish, Tamil, Telugu, Turkish, Urdu and Vietnamese. A regional tag uses its language (de-AT is German), and any other language stays English. Not every translation has been checked by a native speaker yet, and corrections are welcome.

    The translations are plain objects in src/languages/, one file per language. Import one to bundle it, or register texts of your own in PlatyPicker.languages, which win over Platypicker's text by text. A text with a count gives plural forms, picked by the language's own rules.

    Right to left

    In a right-to-left page or element (dir="rtl") the picker mirrors: the popover lines up with the select's right edge, and the chevron, badges and check marks swap sides.

    Browser support

    Platypicker needs anchor positioning (with anchor-scope) and the popover attribute. It uses appearance: base-select where the browser has it, and works without it.

    • Chrome and Edge 135 and later.
    • Firefox, current releases (tested in 160), with no flags.
    • Safari hasn't been tested yet.

    Without support, <platy-picker> does nothing: the select inside it looks and works exactly as a plain one would, so forms keep working everywhere.

    A few things to keep in mind:

    • Only a direct child select is enhanced: <platy-picker><select>.
    • <platy-picker> is display: contents, so size and place the select as you would without it. A multiple select gets a minimum width of 14rem for its badges.
    • Avoid :has() selectors of your own that depend on the options, such as select:has(option:checked). Browsers re-check them for every option that changes, which turns Select all on a long list into seconds of work, in Firefox especially.
    • In Firefox, which has no appearance: base-select, a multiple select is a list box underneath: its options aren't laid out, which keeps a long list fast, so screen readers hear them only in the popover. A letter, Home, End or a page key on it selects one option in place, as in Chrome. The README has the details.
